# 本机组件

程序可以先使用浏览器识别和人工编辑。以下组件按需要安装，依赖与模型存放在项目目录。

## 安装顺序

1. 在项目目录运行 `下载运行环境.cmd`，准备 Node.js、Python 3.11 和基础音频组件。
2. 需要 GPU 时在 PowerShell 运行 `./scripts/安装加速组件.ps1 -GPU`；CPU 原生加速不带 `-GPU`。
3. 器乐六轨使用 `./scripts/安装候选组件.ps1`；可选演唱候选使用同脚本的 `-Singing` 参数。
4. 歌词识别使用 `./scripts/安装歌词组件.ps1`。安装后刷新页面检查组件状态。

需要 NVIDIA CUDA 驱动才能使用显卡计算。界面会显示各阶段实际设备及回退原因；使用高性能不改变音符编辑精度。各模型按需安装，首次下载可能较大。

## 原生后端一致性检查

原生 Basic Pitch 后端在安装后还需要与浏览器基线比较，未通过不会启用。为公开代码提供了基于合成音阶的检查输入：

```text
node scripts/create-compute-fixtures.mjs
node scripts/benchmark-compute.mjs
node scripts/benchmark-compute.mjs --cuda
node scripts/benchmark-compute.mjs --gpu-cpu
```

输入仅有 5 秒合成音阶；不带 --seconds 的命令才会写入后端通过状态，带此参数的快速检查不会启用后端。CPU 只需运行第一项基线检查；GPU 需运行 CUDA 与 GPU 环境的 CPU 回退检查。依次运行，不要同时开启多份检查。合成片段只检验后端一致性，不代表真实歌曲识别质量。

Demucs / CREPE 的显卡检查可按需要运行：

```text
node scripts/qualify-torch.mjs demucs
node scripts/qualify-torch.mjs crepe
```

`requirements-experimental.txt` 列出 CREPE 等实验分析依赖；需安装到项目 Python 环境。安装状态、通过状态、设备是否可用是不同事项，页面给出实际结果。

## 迁移

编辑内容请另存 JSON；音频资源在 `runtime/audio-resources/`。换设备可以复制音频资源，或重新导入原音。Python 虚拟环境不能保证跨路径或跨电脑直接可用，另一台电脑可重新运行安装入口。
