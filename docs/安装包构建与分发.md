# 安装包构建与分发

维护者构建说明。私钥、账号凭据及本机配置不得放入公开目录。

## 工具与产物

需要 Node.js 22+、Python 3.11、Inno Setup 6，以及已审核的旧基础环境 ZIP。优先复用现有环境，不重新下载模型。编译器需安装官方简体中文语言文件。程序包采用 scripts/public-files.json 白名单。

运行 scripts/build-installers.ps1，显式传入 SourceRoot、NodeExe、PythonExe、Compiler、RuntimeZip、PrivateKey、Build 和新的 Output 目录。先运行自动测试和离线构建；输出目录必须不存在。构建编号由私钥旁 issued-builds.json 锁定预留，中断后使用更大编号。

产出两个完整 EXE（lite、base）、共同程序更新 ZIP、NoteMender-update.json 和安装凭据。安装凭据写入两个安装目录 runtime/updates/installed.json；其签名覆盖相同的程序文件。runtime/edition.json 仅说明初始内置组件，真实可用性必须检查文件和环境。

Python 独立解释器组件由 scripts/package-python-component.mjs 从已审核纯解释器目录生成。文件名必须包含实际解释器版本；它独立于日常程序更新，仅在精简版需要分析能力且没有可复用解释器时下载。先上传这个小附件，否则对应下载入口尚不可用。

基础包内 PyAV 的 FFmpeg/编解码库保留原许可。发布时保留既有 runtime-sources 附件及许可证，不把第三方组件改称 MIT。私钥与签发记录在非公开目录备份，不纳入构建目录或上传名单。

## 国内配置

创建真实的 Gitee 公开仓库后，修改 public/distribution.json 的 domesticIndex、domesticPage；整包网盘填 basicShare（仅人工下载）。不假设 Gitee 与 GitHub 账号同名。修改该公开配置后需重新构建并签名。

镜像配置为数组，每项仅 id 和 url；id 可为 domestic 或 github。国内 URL 仅允许已核验的 Gitee/foruda/raw.giteeusercontent 域名。用 scripts/package-update.mjs 的第五个可选参数传入镜像 JSON；第四参数无需上一清单时填 -。所有地址指向同一 ZIP，签名共享大小和 SHA-256，不为不同源生成不同压缩包。

## 发布顺序

1. 检查最终 EXE、ZIP、许可来源材料、说明和附件白名单，不上传 runtime 绑定、工程、音频、日志、私钥及开发记录。
2. 先上传完整安装包、Python 基础解释器组件、共同程序更新 ZIP 和 NoteMender-update.json。Gitee 各镜像目录也提供相同 ZIP 和签名清单。
3. 无登录请求核验各地址、大小、哈希、重定向、续传和下载额度。Gitee 额度、大文件与大陆多运营商实测需维护者补验；不能宣传免费绝不限速。
4. 运行 node scripts/verify-update-release.mjs <输出目录中的 NoteMender-update.json>。它验证全部已声明镜像及旁边的清单，失败就不会生成 index.json。
5. 最后将生成的 index.json 放入 GitHub/Gitee 的 updates/index.json。镜像未就绪不公布；新版本发现依据为版本号和递增构建号。
6. 更新 Gitee 项目首页及发行版说明；安装包链接指向实际整文件。网盘只提供人工下载，不解析登录或绕过限制。

## 检查与恢复

签名与哈希、每次跳转域名、文件清单、解压路径、保存握手、原端口重启和失败回退由现有更新器处理。源码目录受到保护。普通更新不含 runtime；独立解释器也不能作为程序更新载荷。

EXE 没有购买 Windows Authenticode 代码签名证书，系统可能显示“未知发布者”；内部 Ed25519 更新签名不等同于 Windows 安装包证书。提供最终附件 SHA-256 供核对。
